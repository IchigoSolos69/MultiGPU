Build on Windows x64 with PowerShell:

```powershell
./packaging/prepare-compiler.ps1
./packaging/build-windows.ps1
```

The build downloads uv 0.12.22 from Astral's official immutable release and checks its pinned SHA-256. uv prepares CPython 3.12.15 from its pinned managed-Python metadata without registering Python or changing PATH. The compiler preparation checks the official Inno Setup 6.7.3 installer Authenticode signature and publisher before execution. `-PrepareOnly` produces an unpacked payload for testing without the installer compiler.

The Windows host uses the existing .NET Framework and Microsoft's pinned WebView2 WinForms SDK 1.0.4258.31. `prepare-native.ps1` verifies its NuGet package checksum, copies the x64 loader and managed assemblies, and compiles the host plus `MultiGPU.exe` with Windows' .NET compiler. The app reuses its existing four-block mark for its icon and taskbar identity. Source development can run `./packaging/prepare-native.ps1` once before `start.cmd`; installed releases include these components.

Only explicitly named application modules, static files, launchers and README enter the payload. `build-manifest.json` records every included file's checksum. Optional GPU libraries are installed later, after the user requests environment setup. No datasets, exports, credentials or local app database are bundled.

The `licenses` folder contains uv's MIT and Apache license notices from its pinned release. CPython and its bundled components retain their notices inside `runtime`; Microsoft's SDK license remains inside `native`.

The per-user installer targets `%LOCALAPPDATA%\Programs\MultiGPU` and creates a branded Start menu entry for `MultiGPU.exe`. It opens a dedicated native window without browser chrome. The local controller uses its isolated environment at `%LOCALAPPDATA%\MultiGPU\environment`. The default workspace is `%LOCALAPPDATA%\MultiGPU\workspace`; choose another workspace in the tray menu for the next start. Upgrade and uninstall retain the environment, workspace, exports, WebView profile, and provider-native credentials.

Closing the main window hides it to the tray and leaves the controller running. Tray **Open MultiGPU** restores it. **Pause training and exit** requests cooperative pauses where supported, warns about remote executions, and shuts down through the authenticated local API. Provider cancellation and billing enforcement still depend on the provider. The installer is unsigned until a release publisher signs it; Windows may display a reputation warning.

A second launch restores the existing window through a user-restricted local activation event. Separate test configurations have separate instance identities. The default installation retains its installer-visible desktop mutex. Native recovery controls reload a failed WebView, reconnect or restart an unavailable controller, open workspace diagnostics, and exit the window even when the controller cannot answer. Restart reuses saved job identities; it does not submit a second training attempt. A different controller version, Python environment or base runtime requires explicit pause/restart confirmation before reuse.

The launcher offers to repair a missing or incompatible managed Python environment. Repair renames the old environment to a backup and rolls back if creation fails; it does not remove the workspace, exports or provider-native credentials. Optional training libraries must be prepared again after repair. Desktop notification preferences are saved in workspace settings. The tray polls the local controller at five-second intervals with a two-second request timeout, suppresses initial/duplicate alerts, and reports at most three changed runs per poll. Windows notification and focus settings can suppress balloons.

The embedded window permits only the exact local controller origin. User-initiated external HTTPS provider/authentication links open the normal browser; custom schemes, file navigation and other loopback ports are blocked. There is no native host-object or web-message bridge. Local HTTP and same-origin blob downloads use a native Save dialog, including actual training notebooks. Setup instructions and saved checklist progress stay inside the app.

Microsoft Edge WebView2 Evergreen Runtime is required and checked before starting the controller. If missing, MultiGPU explains the prerequisite and asks before running the bundled Microsoft-signed bootstrapper. It never requests administrator elevation; Microsoft's existing shared Edge Updater may manage the installation. Network access is required for this prerequisite. An elevated app asks users to reopen normally instead of silently installing machine-wide. Existing Runtime installations are reused and are not uninstalled with MultiGPU. The missing-runtime installation branch still needs fresh-VM coverage; tests do not remove or reinstall a user's Microsoft Runtime.

Run `./packaging/test-payload.ps1` after building to exercise a relocated payload and an isolated workspace with PATH restricted to Windows system tools. `./packaging/test-installer.ps1` installs the actual release into an isolated build directory, runs the same training/export/restart acceptance, then uninstalls and checks that state and exports remain. It refuses to overwrite an existing registered MultiGPU installation. These tests run on the current Windows host; a separate clean Windows 10/11 VM remains the release gate for SmartScreen, CUDA and provider-authentication checks.

`./packaging/test-tray.ps1` starts the native tray with isolated state, verifies icon/controller readiness, shuts down its empty controller over the authenticated API, and closes only that test tray. Build output includes an installer checksum and `dist/release-info.json` linking it to the exact payload manifest.

`./packaging/test-native.ps1` verifies an actual WebView2 window: DOM rendering, local and blob file downloads, a real guided training notebook download, clipboard write and restoration, exact-origin navigation rules, external-link routing, and hide/restore. It deliberately kills only its own isolated WebView browser, recreates the interface, stops/restarts its controller, verifies its saved job, restores the same host through a second launch, and exits with the controller unavailable. It captures the app's own setup view with the official `CapturePreviewAsync` SDK. Acceptance suppresses external browser launches and uses isolated data; production downloads always show the native Save dialog and disconnected-exit confirmation. `-Source` exercises working source and the prepared source host; the default tests the exact prepared release payload. It can run beside the user's app because its configuration, mutex, browser profile and workspace are separate.

`./packaging/test-native-helpers.ps1` checks instance separation, controller compatibility, notification suppression/bounds and real bundled-environment repair, decline and rollback. It uses the latest prepared payload and writes only new build folders. Windows installer processes start suspended, join a non-breakaway Job Object with `KILL_ON_JOB_CLOSE`, then resume. The `tests.test_process_control` suite verifies owned child-tree cancellation, controller-crash cleanup and refusal of unsafe unsuspended startup.
